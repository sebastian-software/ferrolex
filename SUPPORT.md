# Support

ferrolex is an independent, pre-1.0 Rust engine. Start with the
[README](README.md), the [documentation index](docs/README.md), and the
[contributor guide](CONTRIBUTING.md) before opening a request.

## Usage questions

Search existing issues first, then open a [question](https://github.com/sebastian-software/ferrolex/issues/new?template=question.yml)
with the command or API call, platform, version, and the behavior you are
trying to achieve. Remove credentials and private data from examples.

## Bugs and feature requests

Use the [bug report](https://github.com/sebastian-software/ferrolex/issues/new?template=bug_report.yml)
or [feature request](https://github.com/sebastian-software/ferrolex/issues/new?template=feature_request.yml)
form. Keep bug reports reproducible and focused on one behavior. Public APIs
and compatibility boundaries can change before 1.0, so explain the contract
you rely on when reporting a regression.

## Dictionary-content reports

Use the [dictionary-content report](https://github.com/sebastian-software/ferrolex/issues/new?template=dictionary_content.yml)
for locale compatibility, source-revision, or fixture-evidence questions.
Follow [Compatibility fixtures](docs/compatibility-fixtures.md). The repository
stores reviewed metadata and probes, not third-party dictionary files or their
contents.

## Security

Do not disclose an exploitable vulnerability in a public issue. Contact the
repository maintainers privately through GitHub with the affected version,
impact, and a minimal reproduction that does not include secrets or licensed
data.
